# AI Story Commerce — 架构设计文档

## 1. 总体架构

**Web管理端**：Next.js 16 + React 19 + TypeScript  
页面：项目管理 / 商品管理 / 创意 / 剧本 / 人物 / 成片 / 数据

**业务API服务**：FastAPI + Python 3.11（首期）  
服务：项目服务 / 商品服务 / 剧本服务 / 任务服务 / 审核服务

**AI Agent层**：商品分析、创意、编剧、审核

**生产适配层**：图像、视频、配音、剪辑（适配器架构，禁止与单一模型硬耦合）

**数据层**：SQLite（首期） + SQLAlchemy + Alembic  
保留未来迁移 PostgreSQL 的能力

**文件层**：本地素材、项目文件、成片；统一素材元数据 + SHA256 校验

**人工审批与外部平台**：人工审核、抖音发布、商家交付、数据回收

## 2. 第一版数据库核心表

| 表名 | 用途 |
|------|------|
| projects | 商业项目 |
| products | 商品资料 |
| customers | 商家客户 |
| characters | 虚拟人物 |
| character_assets | 人物参考素材 |
| story_ideas | 剧情创意 |
| scripts | 剧本版本 |
| storyboards | 分镜 |
| production_tasks | 视频生产任务 |
| media_assets | 图片、视频、音频 |
| advertisements | 广告成片 |
| compliance_reviews | 合规审核 |
| publishing_records | 发布记录 |
| performance_metrics | 广告数据 |
| prompt_templates | AI提示词模板 |
| audit_logs | 操作审计 |

关系设计：
- 一个项目可有多个商品
- 一个商品可有多个剧情创意
- 一个剧情创意可有多个剧本版本
- 一个剧本可关联多个角色
- 一个剧本可生成多个分镜
- 一个分镜可产生多个视频素材
- 一个广告可有多个发布记录
- 一个发布记录可关联多组效果数据

必须保留剧本版本和成片版本，不能覆盖历史版本。

## 5. 剧情创作标准

每条15秒广告必须包含：
- 前3秒：钩子
- 第3–7秒：冲突
- 第7–11秒：升级或反转
- 第11–15秒：商品与购买理由

剧情类型：误会型、反转型、逆袭型、悬疑型、荒诞型、对抗型、连续剧型

剧情评分体系（仅供内部创意筛选）：
| 评分维度 | 权重 |
|---------|------|
| 前3秒吸引力 | 20% |
| 故事新颖度 | 20% |
| 冲突与反转 | 20% |
| 商品自然植入 | 20% |
| 人物表现力 | 10% |
| 广告合规性 | 10% |

## 7. 合规审核项目（发布前硬门槛）

| 审核项目 | 要求 |
|---------|------|
| AI生成声明 | 发布前完成 |
| 商品真实性 | 规格、功效、价格可验证 |
| 虚构体验 | 不得冒充真实消费者体验 |
| 人物肖像 | 使用合法授权素材 |
| 声音克隆 | 必须取得相应授权 |
| 音乐素材 | 有商业使用许可 |
| 商标 | 不侵犯他人权利 |
| 广告内容 | 符合广告法及互联网广告管理要求 |
| 发布记录 | 保留版本、平台和发布时间 |

## 8. 开发原则

1. 先审计，后开发
2. 先建立数据结构，再建立业务功能
3. 每个功能必须有测试
4. 每个阶段必须有独立验收
5. 所有AI生成内容必须保留原始输入和输出
6. 所有剧本必须支持版本管理
7. 所有人物必须有固定人物档案
8. 视频生成采用适配器架构，禁止与单一模型硬耦合
9. AI生成、视频生成和发布必须保留人工审批
10. 不得用虚构的广告效果数据作为真实经营数据
11. 不得将内部测试数据伪装成客户案例
12. 不得未经授权发布广告或产生外部费用
